# 分阶段计划

| 阶段 | 工作 | 进入下一阶段的证据 | 当前状态 |
|---|---|---|---|
| 0A 资料核查 | 底板原理图、Linux SDK 架构与 API | 12V/USB-A 已核图；SDK 仅 x86/x86-64，详见核查报告 | 静态核查完成，实机未测 |
| 0 基线 | 导入既有 Buildroot、内核配置、LVGL 工程、启动脚本和固件校验值；确认所有型号 | 可追溯备份和硬件铭牌记录 | 待资料 |
| 1A 供电/枚举 | 按 wiring 检查；运行只读诊断，确认 SocketCAN 或 VCI 路线；VCI 路线须先取得兼容 ARM32 SDK | 电压/电阻记录；dmesg、ip -details 输出 | 方案已准备，实物待测 |
| 1B 单路 | STM32 500k normal 模式；RK CAN1 与 MCU 双向收发；断电改 CAN2 重复 | 每通道实际 0x123→0x321 匹配回复、0x100 心跳、无新增总线错误 | 代码准备，未编译未实测 |
| 1C 通道互测 | 移走 MCU，USB CAN1 ↔ CAN2 同总线双向互发 | 不同接口的抓包和计数变化 | 待测；不是独立双网关验收 |
| 2 HMI 接入 | CAN 采集线程与 LVGL 线程分离；队列更新 UI；超时离线、错误计数、速率、帧数 | 真实帧驱动界面；断线显示离线；保留 vcan 回归模式 | 待既有源码 |
| 3 双网关 | 增加第二现场节点；两独立 CAN 网段；白名单 ID 转发、速率限制、防回环、网络命令鉴权 | 两独立总线互通及故障隔离记录 | 待硬件/实现 |
| 4 负载 | 完成 24V 灯电源、5V 继电器和逻辑驱动；失联默认释放；接触点保护 | 逐路低压负载测试、上电不误动作 | 待规格确认 |
| 5 工业化 | RTC、风扇、看门狗、日志轮转、只读/掉电策略；5m 线、负载和长期运行 | 断电恢复/总线故障/24h 日志、固件回滚 | 待测，不宣称 EMC 或工业认证 |

第一阶段建议每通道至少完成 100 次带递增数据的请求回复和 10 分钟心跳。保存起止计数、漏帧和错误帧；阈值为本项目台架验收目标，不是现有测试成绩。测试时停止旧的虚拟 CAN 自动发送/桥接服务，先记录原配置，避免背景报文污染判断。
